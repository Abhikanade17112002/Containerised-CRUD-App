# 🐳 Multi-Stage Docker Build

The application uses a multi-stage Dockerfile.

The purpose is to separate:

```text
BUILD ENVIRONMENT
```

from:

```text
RUNTIME ENVIRONMENT
```

---

# 📄 Dockerfile

```dockerfile
# ==========================================
# Stage 1: Build
# ==========================================

FROM eclipse-temurin:21-jdk AS build

WORKDIR /app

COPY mvnw .
COPY .mvn .mvn
COPY pom.xml .

RUN ./mvnw dependency:go-offline

COPY src src

RUN ./mvnw clean package -DskipTests


# ==========================================
# Stage 2: Runtime
# ==========================================

FROM eclipse-temurin:21-jre

WORKDIR /app

COPY --from=build /app/target/*.jar app.jar

EXPOSE 8080

ENTRYPOINT ["java", "-jar", "app.jar"]
```

---

# 🧠 Why Multi-Stage Build?

The first stage requires development/build tools:

```text
JDK
Maven
pom.xml
source code
dependencies
```

The second stage only needs:

```text
JRE
Spring Boot JAR
```

Therefore:

```text
Stage 1
JDK + Maven + Source
       │
       ▼
      JAR
       │
       ▼
Stage 2
JRE + JAR
       │
       ▼
Final Docker Image
```

This keeps the final runtime image separate from the build environment.

# ❌ Why Not `localhost:5432`?

Inside the Spring Boot container:

```text
localhost
```

means:

```text
Spring Boot container itself
```

It does **not** mean:

```text
PostgreSQL container
```

Therefore:

```text
jdbc:postgresql://localhost:5432/crud
```

is incorrect when both applications are running in separate containers.

Instead:

```text
jdbc:postgresql://postgres-container:5432/crud
```

should be used.

The successful Spring Boot startup confirms that the application connected to PostgreSQL through the container hostname `postgres-container`. The logs show:

```text

```

and PostgreSQL `17.11` was detected successfully.

```text

        │
```

This uses the Docker network.

# 4. PostgreSQL Database Does Not Exist

If Spring Boot reports:

```text
FATAL: database "cruddb" does not exist
```

check that the database name in Spring Boot matches the PostgreSQL container configuration.

For this project:

```text
POSTGRES_DB=crud
```

Therefore the JDBC URL must use:

```text
jdbc:postgresql://postgres-container:5432/crud
```

and not:

```text
jdbc:postgresql://postgres-container:5432/cruddb
```

This exact mismatch caused a failed Spring Boot container startup during development.

```text

```

check:


# 6. Container IP vs Container Name

Do not configure Spring Boot like:

```text
jdbc:postgresql://172.18.0.2:5432/crud
```

Even though PostgreSQL received an IP from the Docker network.

Instead use:

```text
jdbc:postgresql://postgres-container:5432/crud
```

Why?

Because:

```text
postgres-container
        │
        ▼
Docker DNS
        │
        ▼
Current PostgreSQL IP
```

The container name provides stable service discovery while the underlying container IP can change.
